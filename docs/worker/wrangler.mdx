# Wrangler Configuration

The worker is configured via `wrangler.toml` at the root of the `worker/` directory. This file is the single source of truth for the worker's identity, runtime compatibility, and environment variables.

## `wrangler.toml` Annotated

```toml
# Worker name — identifier for wrangler commands and service bindings
name = "kalidass-journal-worker"

# Entry point — the single ES Module file wrangler bundles and deploys
main = "src/index.js"

# Minimum Workers runtime API version this worker targets
compatibility_date = "2026-09-01"

# Enable Node.js built-in compatibility shims
# Required for crypto.randomUUID() and TextEncoder/TextDecoder
compatibility_flags = ["nodejs_compat"]

# Disable public workers.dev routing and preview URLs
workers_dev = false
preview_urls = false

# Route definition for direct API subdomains
routes = [
  { pattern = "api.kalidass.amrit.fyi/*", zone_name = "amrit.fyi" }
]

[vars]
# CORS origin for allowed client origins
CORS_ORIGIN = "https://kalidass.amrit.fyi"
ROOT_BUCKET = "kalidass"
# Quality evaluation provider (jev | clef | heuristic) and default Cloudflare Clef model selector
EVAL_PROVIDER = "jev"
CLEF_MODEL = "clef-flash"
```

## Key Fields Explained

| Field | Value | Purpose |
| --- | --- | --- |
| `name` | `"kalidass-journal-worker"` | Worker identifier in Cloudflare dashboard and target for Pages Service Binding. |
| `main` | `"src/index.js"` | Single entry point bundled by Wrangler. Imports `memory.js` and `seed.js`. |
| `compatibility_date` | `2026-09-01` | Locks Workers runtime behavior to a specific date, preventing unexpected breaking changes on new runtime releases. |
| `compatibility_flags` | `["nodejs_compat"]` | Enables Node.js compatibility layer for APIs like `crypto`, `Buffer`, `TextEncoder`, and streams. |
| `workers_dev` | `false` | Completely disables public `*.workers.dev` DNS exposure. |
| `preview_urls` | `false` | Disables automated preview deployments on workers.dev. |
| `routes` | `api.kalidass.amrit.fyi/*` | Binds worker directly to custom zone subdomain `api.kalidass.amrit.fyi`. |
| `CORS_ORIGIN` | `"https://kalidass.amrit.fyi"` | Value of the `Access-Control-Allow-Origin` response header. |
| `ROOT_BUCKET` | `"kalidass"` | Root folder prefix inside Upstash Blob for article JSON and media objects. |
| `EVAL_PROVIDER` | `"jev"` | Active quality & safety evaluation provider (`jev`, `clef`, or `heuristic`). See [Quality & Safety Evaluation](/worker/quality-eval). |
| `CLEF_MODEL` | `"clef-flash"` | Cloudflare Clef model selector — `clef-flash` (9B, lowest latency) or `clef` (27B, highest precision). |

## `.wranglerignore`

The `docs/` directory is excluded from all Wrangler operations via `.wranglerignore`:

```text
# Local-only documentation site — not part of Cloudflare Worker deployment
docs/
```

Wrangler only bundles `src/index.js` and its transitive imports (`memory.js`, `seed.js`). The `docs/` directory is never uploaded regardless of this setting, but the ignore file makes the exclusion explicit and protected against future Wrangler features such as `--assets`.

## Local Development

```bash
# Install dependencies
npm install

# Start the dev server on port 8787, bound to all interfaces
npm run start
# Equivalent: npx wrangler dev --port 8787 --ip 0.0.0.0
```

With `UPSTASH_BLOB_TOKEN` set in `.dev.vars`, the worker connects to the live Upstash bucket. Without it, articles are served from an empty in-memory store (no seeded articles).

## Deployment

```bash
# Deploy private worker to Cloudflare edge
npx wrangler deploy
```

## Health Check

In production, test the health endpoint via the Cloudflare Pages edge proxy:

```bash
curl https://kalidass.amrit.fyi/api/health
```

Expected production response:

```json
{"ok":true}
```
